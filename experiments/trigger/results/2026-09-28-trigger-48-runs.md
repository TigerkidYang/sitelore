### opus-B-github-release-1

**Release dates render without a year; read the relative-time datetime attribute** (github.com)

_applies when:_ Logged out, English UI, repository Releases list and single-release tag pages

On a repository's release pages, the publish date is rendered by a `relative-time` element whose visible text is abbreviated and often omits the year (e.g. "04 Sep 22:40") or shows a relative phrase like "3 weeks ago", depending on how long ago the release was. Reporting that visible text alone risks a wrong or missing year. The exact UTC timestamp is in the element's `datetime` attribute, so read that instead of the rendered text. Also useful: appending /releases/latest to a repo URL redirects straight to the current latest release's tag page, which avoids scanning the list and misreading a pre-release as latest.

### opus-C-wikipedia-2

_applies when:_ English Wikipedia (en.wikipedia.org), not logged in, current Vector 2022 layout; applies when reading infobox values as text rather than from the visual layout.

### sonnet-C-github-release-1

**Release publish date isn't in the accessibility tree as plain text** (https://github.com)

On a release page (e.g. /microsoft/playwright/releases/tag/vX.Y.Z), the publish date is rendered inside a <relative-time> custom element and doesn't show up as a plain digit string in the snapshot/find results (it renders as a relative or short date in the visible DOM but the accessibility node text can be inconsistent to search for). Easiest way to get the exact date: run browser_evaluate and read document.querySelector('relative-time').getAttribute('datetime'), which gives an ISO 8601 timestamp.
